# 数学記事フォーマット指南書

> 状態: schema version 1 正式採用
> 対象: 算数、初等数学、初等幾何、初等統計、公理・論理を含む、全年齢向けの数学記事
> 完全サンプル: [長方形の面積](../concepts/catalog/geometry/rectangle-area/ja.md)
> コピー用: [日本語記事の最小テンプレート](./templates/concept-ja-minimal.md)

この文書は、数学記事を書く人のための編集上の基準である。厳密なスキーマと安全性の契約は、共通エンジンの[コンテンツ契約](../../knowledge-engine/docs/content-contract.md)を正とする。

## 5分で始める

1. 既存の概念ディレクトリ、または新しい概念ディレクトリに `concept.yaml` と `ja.md` を置く。
2. [最小テンプレート](./templates/concept-ja-minimal.md)を `ja.md` へコピーする。
3. `summary` に定義・定理・公式の内容を一文で書く。
4. `## 説明` を書き、原則として1〜2題の例題を加える。
5. リポジトリのルートで次を実行する。

```sh
pnpm --dir mathematics check
```

6. 必要に応じてローカルプレビューを起動し、表示と操作を確認する。

```sh
pnpm --dir mathematics dev
```

現在の完全な実装例は「長方形の面積」である。「自然数」「数直線」は構造確認用の短い下書きであり、完全な構成例ではない。

## 基本方針

記事を年齢別の読み物にはせず、数学的に正確な用語を使いながら、初めて読む人にも分かる短い文で説明する。対象とする読解学年がある場合は `readingLevel` を記録し、その基準で読みづらい漢字をルビで補う。

- 冒頭で定義・定理・公式の内容を一文で示す。
- 直感的な説明と数学的に正確な説明を両立する。
- 図、式、文章が同じ内容を表すようにする。
- 数、計算、図形、測定、データなど、具体物・位置・量・変化を扱う記事には、原則として操作できる主図解を1件置く。
- 証明の中心となる発想は本文に示し、長い詳細や別証明だけを折りたたむ。
- 例題は少数に絞り、基本的な適用例と、誤解しやすい例・境界例・反例を優先する。
- 図やJavaScriptを利用できない場合にも、本文と静的表示から内容が分かるようにする。
- 参考サイトの文章や図を再現せず、構成上の長所だけを取り入れる。

この指南書では次の語を使い分ける。

| 区分 | 意味 |
| --- | --- |
| 必須 | スキーマ、ビルド、または公開品質のために必要 |
| 原則 | 通常の記事で従う。外す場合は内容上の理由を持つ |
| 任意 | 理解に役立つ場合だけ加える |
| 禁止 | 安全性または互換性のため使用しない |

## ファイルの役割

一つの概念は、言語に依存しないメタデータと、言語ごとの本文から成る。

```text
concepts/<任意の整理用ディレクトリ>/
├─ concept.yaml
├─ ja.md
├─ en.md
└─ assets/
```

- `concept.yaml`: 安定ID、前提概念、関連概念を記録する。
- `ja.md`: 日本語の記事本文と、日本語固有の読解水準・出典を記録する。
- `assets/`: 自作画像など、その概念に属するローカル素材を置く。

静的SVGは `assets/` の独立したファイルとして置き、Markdownから通常の画像記法で参照できる。ただし、値・形・分類・測定結果を動かして確かめる内容では、静止画を主図解の代わりにしない。静止画は証明中の固定された配置や、操作図を補う必要がある場合に限る。記事本文へSVG要素を直接書いてはならない。SVG資産は自作または利用条件を確認した静的な図に限り、`script`、`foreignObject`、`iframe`、イベント属性、外部URL、`data:` URL、外部CSS、アニメーションを含めない。`title` と `desc` を付け、Markdown側にも図の内容を表す代替テキストを書く。SVG資産は自動監査の許可リストを通す。

このサイトはAstroの `passthroughImageService` を使い、画像をビルド時に変換しない。SVGは不要なメタデータを除いて自己完結させ、ラスター画像は配置前に表示寸法に合う形式・画素数・容量へ最適化する。画像変換が必要になった場合は、記事ごとに別実装を足さず、サイト全体の画像サービスを再設計する。

ディレクトリ名は整理用であり、概念IDではない。移動や改名によってIDや関係を変えてはならない。

```yaml
schemaVersion: 1
id: math/geometry/rectangle-area
prerequisites:
  - math/geometry/rectangles
  - math/measurement/area-as-quantity
  - math/measurement/length
  - math/arithmetic/multiplication
related: []
```

`prerequisites` は、その記事を読む直前に理解している必要がある**直接の学習前提**だけを記録する。前提の前提を重ねて列挙しない。論理的な基礎づけには役立っても先に読まなくてよい形式的概念、別解、発展先は `related` に置く。`related` は前提ではない関連概念である。参照するIDはすべて存在する必要があり、前提関係の循環はビルドエラーになる。本文中の「前提知識」節は読み手への短い確認であり、正式な関係は `concept.yaml` に記録する。

学年を指定した記事から、それより後の学年の記事へ `prerequisites` を張らない。後学年で形式化される内容を直感的に使う場合は、本文内で必要な分だけ説明し、形式的な記事を `related` にする。公理・論理など学年を持たない分枝では、形式的な導出順を `prerequisites` としてよい。

`prerequisites: []` は「前提概念がない、またはこの概念カタログ内では前提なしと確認した」という判断を表す。まだIDを確定できない場合の仮置きとして空配列を使わない。subagentは候補ID、根拠、未確定の理由を成果報告へ列挙し、統合担当者が `review` へ進める前に確定する。独立した検証fixtureで外部IDを参照できない場合だけ、fixture内では空配列とし、候補を検証報告へ残す。

## Frontmatter

日本語本文の先頭には次のfrontmatterを置く。

```yaml
---
locale: ja
title: 記事名
summary: 定義・定理・公式の内容を一文で示す。
readingLevel:
  curriculum: jp-mext-2017
  grade: 4
sources:
  - title: 出典名
    url: https://example.com/
    note: 参照した範囲や用途
status: draft
---
```

| フィールド | 必須性 | 内容 |
| --- | --- | --- |
| `locale` | 必須 | ファイルの言語。日本語は `ja` |
| `title` | 必須 | ページのH1になる短い記事名 |
| `summary` | 必須 | 見出しなしで表示される一文の定義・定理・公式 |
| `readingLevel` | 任意 | 文章を無理なく読める最低学年の目安 |
| `sources` | 必須 | 1件以上の出典。各項目に題名、HTTP(S) URL、参照箇所と確認内容を書く |
| `status` | 必須 | `draft`、`review`、`published` のいずれか |

`readingLevel` は年齢制限でも、数学的な前提関係でもない。`jp-mext-2017` では `grade` に1〜12の整数を指定する。

`readingLevel` に合わせて文章やルビを調整しても、数学用語の定義や主張の範囲を不正確に狭めてはならない。必要な前提が対象学年を超える場合は、前提概念を短く説明するか `concept.yaml` に記録し、定義そのものを別の意味へ置き換えない。

学校算数や初等教育の読者を明確に想定する記事では、原則として `readingLevel` を指定する。意図的に省略する場合は、その理由を成果報告やレビュー記録に残す。指定がなくても、難しい専門語や記号の初出説明を省略してよいわけではない。

`title` と `summary` は現在プレーンテキストであり、数式やdirectiveを記述できない。対象学年で読めない漢字が避けられない場合は、まず読みやすい言い換えを検討する。YAMLへruby directiveやHTMLを書いてはならない。構造化された `titleReading`・`summaryReading` は将来のスキーマ候補であり、現行仕様ではない。

ページ側が `title` をH1、`summary` を見出しのない冒頭文として表示する。このため、Markdown本文にはH1と冒頭文を重ねて書かず、`## 説明` から始める。

状態は次の目安で進める。

- `draft`: 執筆中、未検証、またはAIによる下書きを含む。
- `review`: 数学的内容、出典、表現、表示の人手確認を求める段階。
- `published`: 必要な確認を終えて公開可能な段階。

## 記事の標準構成

| 順序 | 節 | 基準 |
| --- | --- | --- |
| 1 | 冒頭文（見出しなし） | 必須。frontmatterの `summary` |
| 2 | `## 説明` | 必須 |
| 3 | `## 例題` | 原則。通常1〜2題 |
| 4 | `## 練習問題` | 任意。通常2〜4題 |

### 1. 冒頭文（見出しなし）

`summary` に説明する概念を一文で書く。

- 定義の記事では、その言葉が何を意味するかを書く。
- 定理の記事では、前提と結論が分かる形で定理を述べる。
- 公式の記事では、何をどの条件で求める式かを示す。
- 「この記事では〜を説明します」のような学習案内だけにはしない。
- 例外条件が重要なら、短くても省略しない。

### 2. 説明

本文の最初の見出しを `## 説明` とする。次の小見出しは必要なものだけ置く。

- 前提知識
- 図で考える／図解
- 基本的な性質
- 証明の考え方
- 証明の詳細
- 別の証明

可能なら「具体例または図」「言葉」「式」の順に進める。定義の記事に証明を設ける必要はない。公式や定理では、適用できる条件を明記する。

証明を載せる場合は、証明の見通しや中心となる発想を通常表示する。長い計算を含む完全な証明は折りたたみ表示にし、別証明は方法ごとに分ける。「標準的な証明」と「エレガントな証明」は、実際に異なる理解を与える場合にだけ併記する。

### 3. 例題

原則として1〜2題とする。

1. 定義、公式、定理をそのまま用いる基本例
2. 間違えやすい例、境界例、または反例

各例題には「問題」「考え方」「解答」を含める。解答は `details` で折りたたむ。誤答を示す場合は、誤りの理由と見分け方も説明する。

見出しとラベルは、原則として次の形へ揃える。

```markdown
### 例題 1：内容を表す短い題名

**問題**

問題文を書く。

**考え方**

着目する条件や方針を書く。

:::details{summary="解答を見る"}
解答を書く。
:::
```

### 4. 練習問題（任意）

理解の確認に役立つ記事にだけ2〜4題置く。基本操作を確かめる問題から、理由を説明する問題、条件を少し変えた問題へ段階を付ける。解答には答えだけでなく短い考え方を付け、まとめて `details` で折りたたむ。

### 記事種別による重点

| 種別 | 特に示す内容 |
| --- | --- |
| 定義 | 意味、境界、例、非例 |
| 定理・公式 | 条件、結論、直感、証明または理由 |
| 手順・計算法 | 操作、成り立つ理由、失敗例 |
| 公理・論理 | 定義、公理、定理、例、反例の区別 |
| 統計 | データ、個数、単位、集め方、読み取りの限界 |

## 全年齢向けの文章

- 原則として「です・ます」で統一する。
- 正式な数学用語を使い、初出では直後に平易な説明を置く。
- 一文には一つの主要な内容を置く。
- 直感的なたとえと、数学的に保証された主張を区別する。
- 記号だけで意味を説明せず、文章でも読み方と関係を示す。
- 「当然」「自明」「簡単」「常識」のように読者を評価する表現を避ける。
- 子ども扱いする語り口や、学校生活だけに依存する例を避ける。
- 「これから学びます」「学習のポイント」のような学習案内は原則として置かない。
- 小学生向けの内容でも漢字を不自然にひらがなへ開かず、必要な箇所へルビを付ける。

### 重要語句の強調

定義する語、定理の結論、証明や解法の中心となる着眼点は、Markdownの `**太字**` で適度に強調する。

```markdown
:ruby[偶数]{reading="ぐうすう" strong="true"}とは、$2$ で割り切れる整数です。
```

- 初出の定義語や、その段落で最も重要な結論を優先する。
- 1段落の大部分を太字にせず、強調部分だけを拾っても要点を追える程度に絞る。
- 見出し、数式ブロック、calloutですでに目立つ内容へ、重ねて太字を多用しない。
- 強調だけに意味を依存せず、「重要」「結論」「注意」などを文章でも明確にする。
- 装飾目的の斜体・太字・大文字化を避ける。

ルビ付き語句を太字にするときは、Markdownの `**` でdirectiveを囲まず、`ruby` に `strong="true"` を指定する。directiveの境界をまたいでMarkdownの太字記法を書かない。

```markdown
:ruby[偶数]{reading="ぐうすう" strong="true"}
```

下線はリンクと誤認されやすく、現行の安全なMarkdown契約には登録されていない。raw HTMLの `<u>` は使用せず、通常の重要語句には太字、まとまった注意には `callout` を使う。将来、語句の対応付けや証明中の参照箇所など、太字とは異なる教育上の役割が明確になった場合に、安全なdirectiveとして追加を検討する。

## 数式

| 内容 | 表示方法 |
| --- | --- |
| 文中の数、単位、短い式 | インライン数式 `$...$` |
| 中心となる定義式・公式 | ブロック数式 `$$...$$` |
| 複数段の計算、比較、連立 | `aligned` などを使うブロック数式 |
| 計算後の説明文 | 通常の文章。必要な値だけインライン数式 |

```markdown
正方形は全部で $3 \times 4 = 12$ 個なので、面積は $12\,\mathrm{cm}^2$ です。

$$
\text{長方形の面積} = \text{縦} \times \text{横}
$$
```

- 数式をバッククォートのコード表記やUnicodeの上付き文字だけで代用しない。
- 単位は数値との間に狭い空きを置き、立体で表す。例: `$12\,\mathrm{cm}^2$`。
- 角度は `$90^\circ$` のように書く。
- 複数行の計算は `aligned` などで等号や関係を揃える。
- `$$` 内でソースを改行するだけでは表示上の改行にならない。段階計算は `aligned` などで明示する。
- 数式中の日本語だけで説明を完結させず、本文でも意味を説明する。
- 数式内にはルビを付けられないため、必要な読みは前後の本文で示す。
- ギリシャ文字や装飾付き文字を初めて使うときは、意味と読みを本文で示す。例: `$\alpha$（アルファ）`、`$\bar{x}$（エックスバー）`。

記事にはTeX原文だけを書き、KaTeXが生成するHTMLやCSS classは書かない。KaTeXは現在のレンダリングbackendであり、記事フォーマットそのものではない。可搬なTeX subsetを守れば、将来MathJaxなどへ交換できる。

通常の数学・物理・情報学では標準的なTeX記法を使う。化学式と化学の単位には公式 `mhchem` 拡張の `\ce{...}` と `\pu{...}` を使用できる。`\require{mhchem}` は書かない。

禁止するTeXの例は、マクロ定義、パッケージ読込、リンク、HTML、画像、式番号・参照である。不正・未対応の式はフォールバック表示せずビルドエラーになる。

上限は1式2,048文字、1翻訳200式、TeX原文の合計20,000文字である。詳細と将来のbackend変更条件は[数式レンダリングADR](../../knowledge-engine/docs/decisions/0004-build-time-article-math.md)を参照する。

## 図解

図は装飾ではなく、本文中のどの関係を示すかを明確にする。

主図解を選ぶ前に、学習目標を「読み手が何を動かし、何が変わらないことを確かめるか」という一文にする。caption、操作部品、図の変化、結果表示は、その一文に同じ意味で対応させる。たとえば合同の記事で二図全体を一緒に回すだけでは、重ね合わせを確かめられないため不十分である。図が動くこと自体をinteractiveの目的にしない。

| 説明したい内容 | 選択 |
| --- | --- |
| 数・計算の意味 | おはじき、十進ブロック、数直線、分数テープなどの登録済みinteractive |
| 図形の定義・性質 | 点や図形を動かせる登録済みinteractive |
| 長さ・かさ・重さ・時刻 | 定規、計量カップ、はかり、時計などの登録済みinteractive |
| 分類・集計・グラフ | 具体物カードから表やグラフへつながる登録済みinteractive |
| 証明中の固定された空間関係 | 必要に応じて静止図、簡単なSVG |
| 項目の比較 | 表 |
| 純粋形式概念で図が理解を増やさない | 図を省略できる |

小学校第3学年までの収録範囲では、純粋形式概念として明示した記事を除き、登録済みinteractiveを必須とする。図を省略できるのは、具体物、位置、量、変化、対応関係を操作しても理解が増えず、本文と数式だけの方が誤解が少ない場合に限る。「実装するmodeがまだない」「作成時間がない」「抽象概念である」という理由だけでは省略しない。ユークリッド幾何の公理のように空間関係を扱う概念や、自然数の演算法則のように具体物の並べ替えで確かめられる概念は、形式的な説明を含んでいても図解対象である。

現在の監査には移行中の暫定省略表がある。新しい有効な図解を採用した記事は、同じ変更で省略表から外す。省略判断は記事ID、図を置かない理由、本文だけで確認できる内容をレビューに残し、無期限の実装待ち一覧にしない。

主図解は原則として1記事1件とし、操作を1〜3種類に絞る。装飾や機能数ではなく、本文の中心概念を具体物と対応付けることを優先する。

すべての図で次を確認する。

- 辺、角、軸、目盛り、単位を図の近くに表示する。
- 色だけで区別せず、形、模様、ラベル、線種も使う。
- 操作できる値と現在値を文字でも表示する。
- 表示する操作は、図または結果のどちらかに必ず目で分かる変化を起こす。変化しない入力欄は置かない。
- 入力どうしに数学的な制約がある場合（自然数の減法で引く数が引かれる数以下、除数が $1$ 以上など）は、操作部品の `min`・`max`・`step` と現在値にも同じ制約を反映する。図だけを丸めたり、結果だけを別の値へ補正したりしない。
- マウス、タッチ、キーボードのいずれでも操作できるようにする。
- 図上の点・つまみなどを直接動かせる場合も、range、button、selectなどの標準操作を併設する。直接操作と標準操作は同じ状態を更新し、どちらを使っても図、現在値、結果が一致するようにする。
- pointerで押す操作対象は、見た目の記号が小さくても当たり判定を原則44×44 CSS px以上にする。近接する対象どうしは誤操作しない間隔を取る。
- 図には代替説明を付け、同じ内容を本文または静止表示でも説明する。
- 自動再生を避け、初期状態へ戻す操作を用意する。
- JavaScriptが動かなくても初期図、寸法、式、結果が読めるようにする。
- 計算式や単位を含む結果は、初期表示と操作後の表示のどちらにも記事用数式rendererを使う。通常文字の `5 × 3 = 15` や `12 cm²` へ戻さない。
- 具体物は画像ファイルにせず、登録部品が生成する単純なHTML/CSSまたはSVGで描く。
- ドラッグだけに依存せず、ボタン、range、selectなどの標準操作でも同じ状態へ移れるようにする。
- 物理シミュレーション、常時動くanimation loop、自動再生を使わず、操作されたときだけ更新する。
- 記事から任意JSON、座標列、SVG path、色、class、style、数式文字列、イベントを渡さない。

幾何の証明で、角、平行線、交点、対応する位置を文章だけでは一意に指定できない場合は、簡単な静止図を原則として付ける。図中の点名と本文の記号を一致させ、証明自体は図の見た目だけに依存させない。

抽象的な幾何図は、関係を保ったままレスポンシブに縮小してよい。見た目の長さを主張に使わない場合は、必要に応じて「縮尺どおりではない」と示す。

単位マスなど表示寸法そのものが理解に関わる図は縮小して合わせない。

- 1マスの表示寸法を固定する。
- 図が表示枠を超える場合はスクロールさせる。
- 全体寸法と1マスの寸法を常時表示する。
- マス番号など、数え方を確かめる補助表示を必要に応じて切り替えられるようにする。

現在の長方形の面積図は、1マスの一辺を `1 CSS cm` に固定する。CSSの `cm` は端末の解像度や表示倍率の影響を受けるため、物理的な1 cmを保証しない。実寸が教材要件なら、定規などを使った端末ごとの較正機能を別に設ける。

「長方形の面積」は、操作図の見た目と状態同期を確認する基準サンプルでもある。主図解では少なくとも次を同じ品質で確認する。

- caption、操作部品、図、結果を一つの図解カードとして視覚的にまとめ、本文との境界が分かるようにする。サイト共通の色・余白・角丸・focus表示を使い、記事から固有の色やstyleを指定しない。
- captionの直後に意味の分かる操作部品と現在値があり、初期状態でも何を変えられるか分かる。
- 寸法線、括弧、目盛り、辺名、単位など、本文の主張に必要な注記を図の近くへ常時表示する。
- 操作後の具体物、可視ラベル、数式、単位、読み上げ用状態を一回の状態更新で同期する。
- 固定縮尺が意味を持つ図は縮小して枠へ合わせず、横方向を含めて必要な範囲をscrollできるようにする。抽象的な形だけを扱う図は、関係を保つ限りレスポンシブに縮小してよい。
- 操作名は「ひとつめ」のような内部都合の名称ではなく、「横の長さ」「切り口の位置」「□に入れる数」のように学習目標と対応させる。
- UI中の漢字は記事の `readingLevel` とルビ方針に従い、数、式、単位は本文と同じ記事用数式rendererで表示する。操作後に通常文字へ戻さない。

```markdown
::interactive[縦と横を変えて面積を確かめる]{kind="rectangle-area-grid" rows="3" columns="4" unit="cm" captionReading="たてとよこをかえてめんせきをたしかめる"}
```

未登録の図解が必要な場合、記事へJavaScriptやコンポーネントのパスを書いてはならない。新しい `kind` は、エンジン側でスキーマ、許可リスト、静的fallback、アクセシビリティ、統合テストを揃えて追加する。

### 静的図との使い分け

静的図は、証明で点名と位置関係を固定する、反例の一配置を示す、操作図の初期状態を印刷可能な形で補う、といった用途に使う。値、位置、分類方法、測定操作を変えて性質を確かめることが学習目標なら、静的図だけで代用しない。逆に、固定された一配置を正確に参照する証明へ目的のないsliderを付けない。

interactiveのビルド時表示は静的図の代替説明も兼ねる。JavaScript無効時にもcaption、初期図、寸法・単位、初期結果を読めるようにし、画像だけに数学的情報を閉じ込めない。

### 記事とmodeの整合監査

図解が存在するだけでは掲載条件を満たさない。公開範囲の中で誤対応の影響が大きい記事は、`scripts/audit-interactives.mjs` の期待表に記事ID、期待する `kind`・`mode` または必要属性、根拠を登録する。まだエンジンにないmodeは警告として記録し、提案名をスキーマとして確定した扱いにしない。modeが実装・採用された変更で警告を必須検査へ昇格する。

期待表は全記事を手作業で複製する台帳ではない。記事の学習目標と現modeが明確に食い違う場合、同じmode名でも必要な状態が欠ける場合、回帰しやすい代表例に限定する。監査警告を消すためだけにcaptionを図へ合わせて弱めてはならない。採用した契約と段階導入の根拠は[操作図の意味的interactionに関するADR](../../knowledge-engine/docs/decisions/0007-semantic-article-diagram-interactions.md)に記録する。

おはじきなどの個別物体は、数え間違いが起きない範囲に上限を設ける。大きな数は十進ブロックや位取り板へ切り替える。さいころは決定的な初期値を表示し、読み手が「振る」操作をしたときだけ値を変える。二つのさいころを一度に振る図では、1回の操作で記録する目は2個であり、「試行2回」とは数えない。計量カップは液面、時計は連動する長針・短針、はかりは左右の量と傾きを同時に表示する。

## 漢字とルビ

`readingLevel: { curriculum: jp-mext-2017, grade: N }` を指定した場合は、文部科学省の学年別漢字配当表を基準にする。

| 漢字・場所 | 基本方針 |
| --- | --- |
| 対象学年より後の配当、または配当表外 | 原則として毎回 |
| 対象学年の配当 | 記事内の初出 |
| 対象学年より前の既習漢字 | 原則として付けない |
| 中核となる数学用語 | 必要なら繰り返す |
| 見出し、図、折りたたみ見出し | そこから読み始めても分かるよう判断 |
| 「縦・横」などの対語 | 両方を揃える |

学年内のどの時期に各漢字を習うかは配当表だけでは分からない。数学用語、公開時期、読者の必要に応じて追加してよい。完全サンプルでは、中核語、見出し、対話UIから読み始める場合を考え、「面積」「縦」「横」などのルビを意図的に繰り返している。

初出の判定には、太字、リンク、見出し、表、図のcaption内も含める。対象学年より後の漢字や配当表外の漢字は、二回目以降も原則としてルビを付ける。

配当学年を記憶だけで推測せず、公開前に上記の文部科学省資料またはプロジェクトで管理する配当データと照合する。現行validatorはdirectiveの構文と読みの対応を検査するが、対象学年に必要なルビがすべて付いたかは判定しない。本文、見出し、callout、details、図のcaptionを最後に通読し、確認できない語は成果報告へ列挙する。

raw HTMLの `<ruby>` は使わず、登録済みdirectiveで読みを明示する。

```markdown
:ruby[面積]{reading="めんせき"}
:ruby[掛け算]{reading="かけざん"}
```

ルビは漢字の連続部分だけに付く。送り仮名、ひらがな、カタカナ、記号、数字、英字は通常文字のまま残る。上の「掛け算」では「掛」と「算」にルビが付き、「け」には付かない。

通常の `reading` では、非漢字部分を原文どおりに含める。繰り返す仮名などのため対応が曖昧な場合は、漢字の連続部分ごとの読みを `|` で区切る。

```markdown
:::details{summary="練習問題の解答と考え方" summaryReading="れんしゅうもんだい|かいとう|かんが|かた"}
解答を書く。
:::
```

自動で全漢字へ読みを付けると、数学用語や固有名詞を誤読する可能性があるため行わない。

## Directive早見表

本文では、次の登録済みdirectiveだけを使用できる。

| Directive | 用途と主な制限 | 使用場所 |
| --- | --- | --- |
| `ruby` | label 1〜32文字、`reading` 1〜64文字。重要語には `strong="true"` | インライン |
| `callout` | `type` 必須、titleは任意で最大80文字、`titleReading` は任意、本文必須 | 記事直下、または `details` 直下 |
| `details` | summary最大120文字、本文必須、`open` は `true` / `false` | 記事直下 |
| `interactive` | caption最大120文字、登録済み `kind` のみ | 記事直下 |

`titleReading` は最大120文字、`summaryReading` は最大160文字、`captionReading` は最大180文字である。container directiveの閉じ `:::` は独立した行に置く。1翻訳あたりdirectiveは256個、interactiveは8個までである。

### `callout`

補足、ヒント、注意、重要事項に使う。本文構造や見出しの代わりにはしない。

```markdown
:::callout{type="note" title="単位" titleReading="たんい"}
1マスの面積は $1\,\mathrm{cm}^2$ です。
:::
```

`type` は `note`、`tip`、`warning`、`important` のいずれかである。

### `details`

解答、完全な証明、長い計算、別解など、最初から見えなくても主旨を損なわない内容に使う。定義、適用条件、証明の中心発想は隠さない。

```markdown
:::details{summary="証明の詳細" summaryReading="しょうめいのしょうさい"}
ここに通常のMarkdownで証明を書く。
:::
```

### `interactive`

記事直下に置き、子本文は持たない。すべての数値も引用符付き属性として書く。`kind` ごとに許可された属性と `mode` だけを使用し、不要な属性を付けない。正確な上限と組合せは共通エンジンのコンテンツ契約を正とする。

| `kind` | 主な用途 | `mode` | 主な属性 |
| --- | --- | --- | --- |
| `counter-mat` | おはじきによる計数・番号・加減・まとまり・分配 | `count`, `label`, `compare`, `compose`, `decompose`, `add`, `subtract`, `inverse`, `group`, `share`, `remainder`, `multiply` | `value`, `second`, `selected`, `max`, `groups` |
| `place-value-board` | 十進ブロック、位取り、繰り上がり・繰り下がり | `place-value`, `regroup-add`, `regroup-subtract`, `large`, `decimal`, `multiply`, `divide` | `value`, `second`, `max`, `operation`（`decimal`のみ） |
| `number-line` | 順序、0、加減、小数、分数、距離 | `order`, `zero`, `jump-add`, `jump-subtract`, `fraction`, `decimal`, `distance`, `elapsed`, `estimate` | `min`, `max`, `value`, `second`, `step` |
| `fraction-model` | 分数テープと単位分数 | `unit`, `count`, `compare`, `add-subtract`, `decimal` | `parts`, `selected`, `second`, `secondParts`, `operation` (`add-subtract`のみ) |
| `equation-balance` | 等号、未知数、演算の性質 | `equality`, `unknown`, `properties` | `value`, `second`, `selected`, `max`, `operation`（`properties`のみ） |
| `geometry-lab` | 点、線、角、多角形、合同、円、立体、敷き詰め | `point-line`, `segment`, `recognize`, `compose`, `elements`, `position`, `triangle`, `quadrilateral`, `rectangle`, `square`, `right-angle`, `congruence`, `isosceles`, `circle`, `sphere`, `solid`, `tiling`, `euclidean` | `value` |
| `measurement-lab` | 比較、定規、単位タイル、計量カップ、時計、はかり | `compare`, `conservation`, `nonstandard`, `standard`, `length`, `metric-length`, `area`, `capacity`, `metric-capacity`, `mass`, `clock`, `duration`, `elapsed`, `seconds`, `kilometres`, `unit-relations`, `choose-tool` | `value`, `second`, `selected`（`compare`のみ）、`max`, `step`, `unit` |
| `data-lab` | 分類カード、集計、表、絵グラフ、棒グラフ、さいころ | `classify`, `criteria`, `frequency`, `pictograph`, `table`, `bar`, `two-way`, `evidence`, `dice-frequency` | `value`, `second`, `selected`, `third`〜`sixth`, `max`, `categories` |
| `soroban-board` | そろばんの数と計算 | `number`, `calculate` | `value`, `second`, `max` |
| `rectangle-area-grid` | 固定寸法の単位マスによる長方形の面積 | なし | `rows`, `columns`, `unit` |

```markdown
::interactive[おはじきを合わせて足し算を確かめる]{kind="counter-mat" mode="add" value="5" second="3" max="20" captionReading="おはじきをあわせてたしざんをたしかめる"}

::interactive[時計の針を動かして時刻を読む]{kind="measurement-lab" mode="clock" value="7" second="30" max="60" step="5" unit="minute" captionReading="とけいのはりをうごかしてじこくをよむ"}

::interactive[三角形の頂点を動かして、辺と頂点の数を確かめる]{kind="geometry-lab" mode="triangle" value="15" captionReading="さんかくけいのちょうてんをうごかして、へんとちょうてんのかずをたしかめる"}

::interactive[さいころを振って個数を集計する]{kind="data-lab" mode="dice-frequency" value="6" second="4" max="12" categories="6" captionReading="さいころをふってこすうをしゅうけいする"}
```

`rectangle-area-grid` の `rows` と `columns` は1〜12、`unit` は `mm`、`cm`、`m` のいずれかとする。family型の図解は、具体物を大量生成しない上限、分数の選択数が分割数を超えないこと、数直線の点が表示範囲内にあることなども検証される。

`measurement-lab/compare` の `selected="0"` は端をそろえる直接比較、`selected="1"` は同じテープへ写す間接比較を表す。`measurement-lab/capacity` では `value` を水の全量、`second` をAからBへ移す量として指定し、`second` は `value` 以下にする。Bに入り切らない分も「あふれ」として描き、A・B・あふれの合計が全量と一致しなければならない。単位換算を比べる `metric-capacity` とは意味を混同しない。

`data-lab` で3区分以上を表示するときは、各区分の値を `third`、`fourth`、`fifth`、`sixth` へ必要な数だけ明示する。表示区分をゼロで埋めたり、別の値から根拠なく推測したりしない。

## 分野別の注意

### 数と計算

- 具体物、数直線、位取り表など、計算の意味が分かる表現を優先する。
- 手順と、その手順が成り立つ理由を分ける。
- 0、単位、繰り上がり、余りなどの境界を確認する。

### 図形と測定

- 図に辺、角、長さ、単位を直接対応させる。
- 見た目に依存する主張は、条件を明記する。
- 面積と周の長さなど、混同しやすい量を比較する。
- 図を動かしても変わらないものと、変わるものを区別する。

### 統計

- データの出典、個数、単位、集め方を明記する。
- 表やグラフには軸名、目盛り、単位を付ける。
- 代表値だけで結論を出せない例や、誤解しやすい読み方を示す。
- 実在データを使う場合は、利用条件と個人情報を確認する。

### 公理・論理

定義、公理、定理、例、反例を区別する。公理は「証明なしに出発点として採用する命題」と説明し、定理と混同しない。生活語による直感だけで終えず、必要に応じて記号や場合分けも併記する。

### 物理・化学・情報学へ広げる場合

- 物理量は数値、単位、符号、座標系、近似条件を区別する。
- 化学式・反応式は `mhchem` を使い、物質名、状態、条件も文章で説明する。
- 情報学のコードは数式と混同せずコードフェンスへ置き、実行可能な記事コードにはしない。
- 各分野で新しい対話部品が必要なら、記事ではなくエンジン側の登録部品として設計する。

## 出典・著作権・公開状態

- 数学的事実、教育課程、統計データには、可能な限り一次資料を使う。
- `sources[].note` に、参照した節・ページ・確認した内容を書く。
- 外部画像を無断転載せず、自作図または利用条件を確認した素材を使う。
- 自作図でも、他サイトの図の配置・色・説明をそのまま再現しない。
- AIが作成した下書きは、人が数学的内容と出典を確認するまで `draft` とする。

`draft` であっても `sources: []` は使用しない。執筆に用いた一次資料または信頼できる確認元を1件以上記録し、`note` には「第3章第1節、pp. 78–87。第1学年で扱う数の範囲と用語を確認」のように、**参照した節・ページと確認した内容**を書く。検索結果ページ、生成AIの回答、本文を確認していない資料は出典にしない。

数学ドメインのAstroスキーマは共通エンジンより厳しく、出典を1件以上、題名・URL・10文字以上の注記を含むmappingとして要求する。`example.com` などの例示用ドメインは拒否するため、テンプレートの値は必ず実在資料へ置き換える。

## 分業で作成する場合

複数の記事を作る際は、次の役割を並行させられる。

1. 本文作成: 冒頭文、説明、例題、練習問題を書く。
2. 図解設計: 静止図、対話的図解、代替説明を設計する。
3. 出典確認: 数学的事実、教育上の用語、素材の利用条件を確認する。
4. レビュー: 正確性、読みやすさ、アクセシビリティ、前提関係を点検する。

担当者は前提知識や関連概念を独断で確定せず、候補と根拠を返す。統合後も人による確認が終わるまでは `draft` とする。

成果報告には少なくとも、指定または省略した `readingLevel` の理由、学年別配当表との照合結果と未確認語、前提・関連概念の候補、使えずに見送った図解やdirective、指南書で判断に迷った点を含める。

## 安全な記法と制限

- 使用できるのはplain Markdownと登録済みdirectiveだけである。
- MDXとraw HTMLは禁止する。`<ruby>`、`<details>`、`<svg>`、`<br>` も直接書かない。
- 本文からJavaScript、import、コンポーネントパス、任意JSON、event handler、`style`、`class`、任意ARIA属性を渡さない。
- `javascript:` URLと `data:` URLは禁止する。相対リンクと画像はローカルで解決できるものにする。
- SVG資産にも、`script`、`foreignObject`、`iframe`、イベント属性、外部URL、`data:` URL、外部CSS、アニメーションを含めない。
- directive名・属性・値は推測して補正しない。不明なもの、形式違い、誤った入れ子、閉じ忘れはビルドエラーになる。
- directive記法そのものを説明するときは、インラインコードまたはコードフェンスに入れる。
- 記事から生成済みのKaTeX HTMLやSVGを貼り付けない。

## 検証手順

通常の記事変更では、リポジトリのルートから次を実行する。

```sh
pnpm --dir mathematics check
```

これは記事構成、出典、数式表記、ルビ、Astroの型・構文、コンテンツ、manifest、静的ビルドをまとめて検査する。個別監査だけを行う場合は次を使う。

```sh
pnpm --dir mathematics audit:structure
pnpm --dir mathematics audit:sources
pnpm --dir mathematics audit:math
pnpm --dir mathematics audit:prerequisites
pnpm --dir mathematics audit:ruby
pnpm --dir mathematics audit:svg
pnpm --dir mathematics audit:interactives
```

途中のスキーマ検証だけを行う場合は次を使う。

```sh
pnpm --dir mathematics validate
```

directive、数式renderer、共通コンポーネントなどエンジンも変更した場合は、次の順で実行する。

```sh
pnpm --dir knowledge-engine check
pnpm --dir mathematics check
```

ローカル表示は次で確認する。

```sh
pnpm --dir mathematics dev
```

目視・操作では次を確認する。

- PC幅と狭い画面、必要に応じて拡大表示
- 数式、単位、MathMLの表示
- ルビが漢字だけに付き、送り仮名やカタカナへ付いていないこと
- `details` の開閉と、解答が初期状態で隠れていること
- 図の現在値、寸法、式、結果、スクロール、初期化
- 具体物を操作した結果が本文の定義・式と一致すること
- キーボード、タッチ、フォーカス表示
- JavaScriptがない場合にも初期内容を読めること
- 図、本文、式が同じ条件と値を示すこと
- ブラウザconsoleにエラーがないこと

## 公開前チェックリスト

### 数学的正確性

- [ ] `summary` だけで定義・定理・公式の要点が分かる。
- [ ] 定義、公理、定理、例、反例を混同していない。
- [ ] 条件、単位、境界、例外を省略していない。
- [ ] 証明の前提と結論が対応している。
- [ ] 図、文章、式が同じ内容を表している。

### 構成と文章

- [ ] 本文は `## 説明` から始まり、H1や冒頭文を重複していない。
- [ ] 新しい用語を使う前後で説明している。
- [ ] 例題は原則1〜2題、練習問題は必要な場合だけ2〜4題である。
- [ ] 解答や長い証明だけを折りたたみ、中心内容を隠していない。
- [ ] 全年齢向けの語調で、学習案内や読者を評価する表現がない。
- [ ] 重要語句の太字は要点に絞られ、強調だけに意味を依存していない。

### 読みやすさとルビ

- [ ] `readingLevel` が年齢制限や数学的前提として使われていない。
- [ ] 本文、見出し、図、操作UI、折りたたみ見出しをルビ方針に照らした。
- [ ] ルビは漢字だけに付き、送り仮名、ひらがな、カタカナには付いていない。
- [ ] 数式内の日本語ラベルとSVGの可視ラベルは、対象学年で読める漢字か、かな・記号へ言い換えた。
- [ ] 対語と中核語の表記が一貫している。

### 図解・アクセシビリティ・技術

- [ ] 図を利用できなくても本文または静的表示から理解できる。
- [ ] 色だけに依存せず、ラベル、線、形、代替説明がある。
- [ ] SVG資産が静的・自己完結で、禁止要素、イベント属性、外部参照を含まない。
- [ ] 静的図は固定配置の説明に使い、操作して確かめる関係の代用品にしていない。
- [ ] 図解必須の記事に登録済みinteractiveが1件あり、静止画像だけで代用していない。
- [ ] おはじき、定規、計量カップ、時計などの具体物と、数・式・単位が同期している。
- [ ] すべての操作が図または結果へ反映され、変化しない入力欄がない。
- [ ] caption、学習目標、操作名、図の変化、結果が同じ関係を説明している。
- [ ] 直接操作と標準操作が同じ状態へ同期し、キーボードだけでも操作できる。
- [ ] pointer操作対象の当たり判定が原則44×44 CSS px以上ある。
- [ ] 入力の範囲・刻み・相互制約が、図、式、結果、操作部品で一致している。
- [ ] 単位マス図はセルを縮小せず、必要な範囲をスクロールできる。
- [ ] 寸法、目盛り、辺名、単位、現在値が必要な間は常時表示されている。
- [ ] 数・式・単位をインライン数式またはブロック数式で一貫して表した。
- [ ] 出典、画像の権利、AI下書きの人手確認を済ませた。
- [ ] `pnpm --dir mathematics check` が成功する。
